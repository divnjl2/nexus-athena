# Spec: Управление задачами через Telegram + Obsidian (ИНТЭР)

_Логический корень (what + why). Без тех-стека — «как» живёт в design.md._

## Why
Из оргдиагностики ИНТЭР: проблема №1 по сигналам — задачи живут в рабочем чате (432 «планёрки в ленте»), теряются и порождают переделки (293 сигнала). Нужен трекер, где руководитель (Павел) назначает задачи и видит статусы исполнения, а сотрудники ведут свои задачи — без планёрок в чате. Система должна опираться на уже существующие активы: единое хранилище знаний (Obsidian-вольты в S3) и корпоративный Telegram-бот.

## Кто
- **Руководитель / администрация** (Павел и назначенные админы) — назначают задачи, видят своды.
- **Сотрудник** — видит и ведёт только свои задачи.

## User stories
- **US1** — Как руководитель, я назначаю задачу сотруднику (текст + опц. срок), чтобы она появилась в его личном пространстве.
- **US2** — Как руководитель, я вижу статусы исполнения по сотрудникам и по отделам, чтобы контролировать работу без планёрок.
- **US3** — Как сотрудник, я вижу свои задачи и меняю их статус, чтобы отчитываться действием, а не словами.
- **US4** — Как система, я показываю управленческие своды только руководителям, чтобы сохранить приватность между сотрудниками.

## Acceptance criteria (EARS)
- **AC1** — WHEN руководитель назначает задачу сотруднику с текстом и (опционально) сроком, THE SYSTEM SHALL создать задачу в личном пространстве этого сотрудника в статусе «Надо сделать».
- **AC2** — WHEN сотрудник меняет статус своей задачи, THE SYSTEM SHALL отразить новый статус в управленческом своде руководителя без ручного обновления.
- **AC3** — WHEN руководитель запрашивает свод, THE SYSTEM SHALL показать по каждому сотруднику количество задач в разбивке по статусам и перечень просроченных.
- **AC4** — WHEN руководитель запрашивает свод по отделам, THE SYSTEM SHALL сгруппировать сотрудников по отделу.
- **AC5** — WHEN не-руководитель запрашивает управленческий свод, THE SYSTEM SHALL отказать и показать только его собственные задачи.
- **AC6** — WHERE у задачи задан срок, WHEN срок прошёл и задача не завершена, THE SYSTEM SHALL пометить её просроченной в своде.
- **AC7** — WHEN задача создана или изменена через любой из двух интерфейсов (Telegram или Obsidian), THE SYSTEM SHALL сделать изменение видимым в другом интерфейсе (единый источник данных).

## Out of scope (v1)
- Изоляция «сотрудник не видит доки другого» на уровне файлов (решается отдельно через раздельные бакеты; здесь приватность — только на управленческие своды через роль бота).
- Уведомления/напоминания по срокам (следующая итерация).
