# Design: Управление задачами через Telegram + Obsidian

_«Как» (архитектура), выведено из frozen spec.md. Тех-стек: Python, aiogram v3, aiosqlite, boto3, Yandex S3._

## 1. Единый источник данных — S3 (файл доски = истина)
- Бакет `inter-vault`, файлы `<Имя>-Vault/📋 Мои задачи.md` (по одному на сотрудника).
- Формат карточки: `- [ ] <текст> 📅 YYYY-MM-DD #<метка>` под колонкой `## <статус>`.
- **Статус = колонка канбана:** `📥 Надо сделать` / `🔨 В работе` / `⏳ Ожидаю результат` / `✅ Сделано`.
- Отдельной таблицы задач НЕТ. И бот, и Obsidian правят один .md — это исключает рассинхрон «двух правд».

## 2. Два клиента, одни данные
```
Obsidian (десктоп, сотрудник) ⇄ Remotely Save ⇄ [S3 inter-vault] ⇄ boto3 ⇄ TG-бот (мобила)
```
- Obsidian: сотрудник таскает карточки визуально (Kanban-плагин).
- Бот: инлайн-кнопки для назначения/просмотра/смены статуса.

## 3. Модуль бота (расширение corp_attendance_bot)
### 3.1 Маппинг (SQLite, у existующей таблицы employees)
- Новые поля: `vault TEXT` (напр. `Ivan Evolett-Vault`), `department TEXT` (Датчик / Сборка АКБ / Продажи / Лаба / Управление). Роль `is_admin` уже есть.
- Отдел берём из `#сфера/*`-тегов профилей (маппинг уже существует в вольтах) — сид-скрипт заполняет department разово.

### 3.2 S3-модуль `s3board.py` (чистые функции, тестируемые)
- `read_board(vault) -> list[Card]` — тянет .md, парсит колонки+карточки (Card: text, status, due, done, raw).
- `add_card(vault, text, due=None, tag=None)` — read-modify-write: вставляет карточку под «Надо сделать», аплоадит.
- `move_card(vault, card_id, to_status)` — переносит карточку в другую колонку.
- `mark_done(vault, card_id)` — в «Сделано» + `✅ <today>`.
- `report(vaults) -> dict` — агрегат по людям/отделам: счётчики по статусам + просроченные (due < today, не done).
- Идентификатор карточки — стабильный хеш от (vault, нормализованный текст) — чтобы кнопки callback работали без правки формата.

### 3.3 Inline-меню (aiogram InlineKeyboardMarkup + FSM)
- **Меню руководителя:** `[➕ Назначить] [📋 Актуальные] [📊 По сотрудникам] [🏢 По отделам] [🔴 Просрочено]`
- **Меню сотрудника:** `[📋 Мои задачи]`, у каждой задачи inline: `[🔨 В работу] [✅ Готово]`
- **Поток «Назначить» (FSM, всё кнопками):** ➕ → выбрать сотрудника (кнопки-список из employees) → ввести текст (state) → срок (кнопки: `Сегодня` / `+3 дня` / `+неделя` / `Без срока`) → `Подтвердить` → `add_card`.

### 3.4 Роль-гейт
- `Назначить / По сотрудникам / По отделам / Просрочено / Отчёт` — только `is_admin`.
- Сотрудник — только `Мои задачи` (свой vault). Это закрывает приватность управленческих сводов без переделки вольтов.

## 4. Петля статусов (двусторонняя)
- Сотрудник двигает карточку в Obsidian → RS → S3 → бот `report()` читает новую колонку. Актуально без ручного апдейта.
- Сотрудник жмёт `✅` в боте → `move_card` в S3 → RS синкает в Obsidian.
- Оба направления на одних файлах.

## 5. Конкурентность (осознанный компромисс)
- Риск: Obsidian(RS) и бот пишут в один файл → last-write-wins.
- **v1 (MVP):** объём малый (единицы правок/день) + RS `conflictAction=keep_newer` + бот делает атомарный read-modify-write per-операция → коллизии редки, приемлемо.
- **v2 (апгрейд, если объём вырастет):** бот пишет в per-user `📥 _inbox.md` (только бот) + лёгкий merge-хук в доску. Файл-истина сохраняется, гонок нет. Заложено, не реализуем в v1.

## 6. Безопасность
- S3-creds — в `.env` бота на VPS (не в гит). Тот же бакет/ключ, что синкает вольт.
- Callback-данные подписаны/валидируются по user_id (нельзя дёрнуть чужую доску).

## 7. Деплой
- Расширяем существующий Docker-образ бота на VPS (visible-aqua). Миграция SQLite (add columns) + новый env (S3_*). Тесты гоняются в CI перед деплоем.

## Открытые вопросы (QRSPI)
- Q1: отделы — из `#сфера`-тегов автоматически или ручная нарезка оператора? (design допускает оба; сид-скрипт параметризуем.)
- Q2: v1-гонки (файл-истина) vs сразу v2-inbox? (рекомендация — v1, апгрейд заложен.)
