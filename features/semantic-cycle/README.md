# Semantic repair cycle

The opt-in implementation and fresh evaluation have run. Local verification passed
186 regressions and 11 feature specs. This does not establish semantic correctness,
production readiness, or completion on committed and pushed artifacts.
See [evaluation results](evaluation-results.md) for outcomes and evidence boundaries.

`lineage.py` supplies durable admission, protected reservations, crash-pending charges,
typed accounting and complete bound-command cost forecasts. Every revision must use
the same journal. Limits count outer requests and test-tool attempts, not provider
wire retries or server spending. Missing token usage remains unknown.

Journal hashes are fingerprints, not owner authentication. Consumers must pin a
trusted head to detect suffix truncation. Process crash tests do not establish
power-loss durability on every filesystem.

`intent.py` now supplies an issue-only request, exact source anchors, append-only
intent revisions and support-coverage checks for newly introduced syntactic assertions.
Its support decisions remain model declarations, not proofs of implication or a full
inventory of dynamic or indirect oracles. Missing/stale support cannot release a candidate.
Open questions do not prevent proposing a candidate. Every question stays frozen in the
passport and must receive a separate source-checked RESOLVED/NONBLOCKING declaration
before release; missing answers and UNRESOLVED questions keep support INCOMPLETE.
This avoids treating absence of a reproduction or unspecified harmless choices as an
automatic reason to abandon generation. Answers remain advisory semantic judgments.

Optional generation hooks deliver public guidance, expose the shared resource view,
distinguish exploration from native baseline work and observe proposals before tests.
The original baseline behavior remains the default. `cycle.run_cycle` now connects
generation, immutable proposals, fresh issue/profile/candidate review and native audit.
It withholds a candidate with unresolved advisory support without relabelling that
finding as an executed native failure. `semantic.py` rejects identical AST controls
and records declared mechanism/representation distinctions; structural difference is
still not proof of semantic validity. Only the final exact passing patch is released.

`assessment.py` binds disjoint cohorts, execution files and runtimes before inference,
seals every case/arm and candidate before grading, prevents later inference and reports
full outcome matrices, withheld-good finals, repairs and resources. Workflow selection
is sealed before independent grades. The fresh study completed all 30 selected cases
across three arms, retaining unavailable cases as INCOMPLETE. Neither Athena arm
released a final candidate; this evaluation therefore provides no useful acceptance
precision estimate or evidence of improvement over direct generation.

The new cohort is selected before implementation trials, disjoint from the old
35 cases. Runtime and executable bindings must be frozen separately before study
inference. Evaluation reports never enter generation or repair contexts.
